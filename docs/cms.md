# 블로그 관리자

관리자: https://yt010108.github.io/admin/#manage

## 처음 연결

1. 관리자 주소를 열면 GitHub 토큰 로그인 화면을 표시합니다.
2. 토큰 만들기 링크를 눌러 GitHub에서 fine-grained personal access token을 만듭니다.
3. Resource owner는 yt010108, Repository access는 Only select repositories에서 yt010108.github.io만 선택합니다.
4. Repository permissions의 Contents는 Read and write, Actions는 Read-only로 설정합니다. Metadata 읽기는 기본 권한입니다.
5. 만든 토큰을 로그인 창에 입력합니다. 이 브라우저에서 연결 유지 여부를 선택하고 관리자 열기를 누릅니다. 채팅이나 저장소에 토큰을 남기지 않습니다.

연결 유지가 선택되어 있으면 localStorage에 토큰을 보관해 새 탭이나 다음 브라우저 방문에서 복구합니다. 기본으로 선택되어 있으며 공용 PC에서는 해제할 수 있습니다. 해제하면 현재 탭의 sessionStorage만 사용합니다. 저장된 토큰도 방문할 때 GitHub에서 다시 검증하며, 검증 전에는 글 목록과 브라우저 임시글을 불러오지 않습니다.

로그아웃은 두 저장소의 토큰을 모두 지웁니다. 기억하기로 연결한 다른 탭도 잠깁니다. 토큰 만료·폐기 시 다시 로그인하며, 네트워크 오류만 발생한 경우에는 잠금 상태로 저장 정보를 보존하고 저장된 연결 다시 확인을 제공합니다. GitHub 쪽 토큰 자체를 폐기하려면 GitHub 설정에서 삭제합니다. 관리자는 yt010108 계정과 yt010108/yt010108.github.io 저장소로 제한합니다.

GitHub OAuth 앱이나 별도의 인증 서버를 등록하는 방식은 포함하지 않습니다. 현재 GitHub Pages의 관리자 HTML·JavaScript 파일은 공개 정적 파일이며 로그인은 관리 UI를 잠그는 기능입니다. API 권한은 GitHub가 검사하므로 화면 코드를 열어도 유효한 권한 없이 저장소를 수정할 수 없습니다. 관리자 파일 자체를 비공개로 제공하려면 별도의 서버 측 접근 제어가 필요합니다.

## 작성부터 발행까지

1. 새 글을 눌러 제목·종류(Posts/Notes)·카테고리·본문·태그를 작성합니다.
2. 본문과 첨부 이미지는 현재 브라우저에 자동저장합니다.
3. 완료에서 파일 이름·설명·작성일을 확인합니다.
4. 발행하기를 누르면 글·첨부 이미지·목록을 GitHub main에 한 커밋으로 저장합니다. 기존 발행 글은 수정 발행으로 표시합니다.
5. 글 관리의 배포 상태에서 대기·진행·성공·실패를 확인합니다. 배포가 성공하면 블로그에서 보기로 확인합니다.

파일 이름은 문서 메타데이터이며, 공개 글 링크는 글 ID를 사용하므로 제목을 바꿔도 유지됩니다. Markdown 저장과 편집용 백업 저장은 파일 내보내기이고 발행하지 않습니다.

## 글 관리

왼쪽 사이드바에서 글쓰기·글 관리·임시저장·카테고리·태그·휴지통으로 이동합니다. 데스크톱에서는 사이드바가 고정되고, 모바일에서는 메뉴 버튼으로 열고 항목을 선택하면 닫힙니다. 미디어, 페이지·프로젝트의 독립 관리 메뉴는 준비 중으로 표시합니다. 기존 글 관리의 카테고리 필터와 작성기의 이미지 첨부는 계속 사용할 수 있습니다.

카테고리·태그에서 항목을 추가하면 GitHub에 저장하고 글쓰기의 선택 목록에 연결합니다. 각 항목에는 사용하는 글 수를 표시합니다. 이름 변경·삭제를 누르면 영향받는 발행 글과 이 브라우저 저장본의 수를 먼저 보여줍니다. 확인 후 이름 변경은 해당 글의 분류를 함께 바꾸고, 카테고리 삭제는 미분류로 전환하며, 태그 삭제는 해당 태그만 제거합니다. 본문과 이미지는 유지합니다. 공개 글 변경은 한 커밋으로 저장하고, 확인 화면을 연 뒤 원격 목록이 바뀌면 강제로 덮어쓰지 않고 중단합니다. 브라우저 저장본도 버전이 바뀌면 덮어쓰지 않습니다.

- 전체는 휴지통을 제외한 글을 표시합니다.
- 임시글은 아직 발행하지 않은 글과 공개본 이후 수정한 글을 표시합니다.
- 발행된 글은 GitHub에 공개 상태로 저장한 글을 표시합니다. 수정 중인 공개 글은 두 상태 탭에서 찾을 수 있습니다.
- 휴지통은 임시글과 GitHub에서 휴지통 상태로 저장한 글을 표시합니다.
- 검색은 제목·카테고리·태그, 필터는 상태·Posts/Notes·카테고리를 사용합니다.
- 복제는 별도 임시글을 만들며 원래 글의 발행 연결을 가져오지 않습니다.
- 여러 글을 선택해 휴지통으로 이동하거나 복원할 수 있습니다.

발행된 글의 휴지통 이동·복원에는 GitHub 연결이 필요합니다. 휴지통 이동은 공개 빌드에서 해당 글을 제외하고, 복원은 다시 포함합니다. GitHub가 공개 저장소이므로 이전 커밋과 이미지 파일까지 비공개로 바꾸지는 않습니다. 영구 삭제와 비공개 글 기능은 포함하지 않습니다.

## 충돌과 복구

- 같은 임시글을 여러 탭에서 바꾸면 저장 버전을 검사하고 충돌을 표시합니다. 복사본으로 저장해 내용을 보관할 수 있습니다.
- GitHub에서 다른 글이나 코드가 먼저 변경되면 발행을 중단하고 브라우저의 수정본을 보관합니다. 글 관리에서 최신 상태를 확인한 뒤 다시 발행합니다.
- 같은 공개 글의 원격 버전이 바뀌면 최신 공개본 불러오기를 사용할 수 있습니다. 확인 후 현재 수정본을 별도 임시글로 복제하고 최신 글과 이미지를 불러옵니다.
- GitHub 저장에 성공하고 배포가 실패한 경우 GitHub의 글은 남아 있습니다. Actions 링크로 실패 원인을 확인합니다.
- 임시글은 다른 브라우저에 자동으로 동기화하지 않습니다. 편집용 백업으로 옮기거나 발행한 글을 GitHub에서 불러옵니다.

## 저장·배포 구조

- blog/index.json: 글 목록, 상태, 메타데이터, 문서 SHA
- blog/entries/글-ID.json: 본문 문서, 이미지 목록, 메타데이터
- assets/uploads/글-ID/: 첨부 이미지
- published.js: 빌드 시 생성하는 공개 글 데이터
- shared/posts.js: 공개 글과 작성 미리보기의 공통 렌더러

초안 원문과 토큰은 공개 빌드에 포함하지 않습니다. 공개 빌드는 GitHub에 발행한 글만 포함하고, 문서·목록·이미지 SHA가 맞는지 검사합니다. 기존 _posts/와 이전 이미지 원본은 이번 CMS에 자동으로 이전하지 않습니다.

## 검증

npm test는 GitHub 쓰기 트랜잭션, 충돌·실패·응답 유실 복구, 로그인 유지·재검증·만료·저장 실패, 권한 처리, 본문 이스케이프, 공개 빌드를 검증합니다. API 응답을 통제한 테스트이며 실제 토큰을 포함하지 않습니다. 실제 계정의 최초 연결은 관리자에서 직접 진행합니다.
