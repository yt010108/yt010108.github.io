# 개인정보위 결과 공표 수집

GitHub Actions의 `개인정보위 결과 공표 동기화`가 매일 한국시간 09:35에 결과의 공표 게시판 전체 페이지를 확인합니다. `blog/pipc/published.json`의 원문 글 번호와 기존 카테고리 글의 출처를 대조합니다. 새 글은 `Archive / 개인정보보호법 결과 공표`에 원본 첨부파일, 대상 이름, 원문 링크 순으로 게시합니다. [공식 게시판](https://pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS258&mCode=C010040000)

PDF·HWP·HWPX에서는 처분 표의 명칭 열을 읽습니다. 이미지와 스캔 PDF는 한국어 OCR로 명칭 셀을 두 번 읽습니다. 모든 첨부와 쪽의 순번을 확인한 뒤 같은 이름은 한 번만 표시합니다.

## 검토 대기 글 게시하기

1. 워크플로 실행의 Summary에서 검토할 글 번호를 엽니다. `blog/pipc/review/<글 번호>/notice.json`에 사유, 원문 주소, 첨부의 원래 이름이 있습니다. 같은 폴더의 `0.bin` 등은 내려받아 원래 확장자로 열 수 있습니다.
2. 원본에서 대상 이름을 확인합니다. Actions → 개인정보위 결과 공표 동기화 → Run workflow에서 `main`을 선택합니다.
3. `notice_id`에 원문 글 번호, `names`에 확인한 이름을 입력합니다. 여러 곳이면 `기관 A | 기관 B`처럼 구분합니다. 실행하면 보관한 파일의 해시를 확인하고 해당 글을 게시한 뒤 대기 목록에서 지웁니다.

입력을 모두 비우면 즉시 새 글을 확인합니다. 원본 다운로드가 실패하면 실행 요약에 해당 글 번호를 남기고 다음 수집에서 재시도합니다. 새 글을 커밋하면 기존 Pages 배포 워크플로를 실행합니다.
