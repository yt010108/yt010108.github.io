# yt010108.github.io

보안 글, 짧은 학습 노트, 프로젝트를 함께 보여주는 개인 사이트입니다.

- 사이트: https://yt010108.github.io/
- 구성: HTML · CSS · JavaScript
- 호스팅: GitHub Pages, GitHub Actions로 정적 파일 배포

## 화면 구성

- 홈: 자기소개 → 대표 글 → 대표 프로젝트 → 최근 글
- 상단 메뉴: Home → Posts → Notes → Projects. 상단 About 메뉴만 숨기고, 홈의 About me 버튼과 하단 About 링크는 제공합니다.
- 로고: 사이트와 같은 산세리프 계열의 단색 yt 로고를 헤더와 관리자에서 공유하고, 같은 형태의 파비콘을 사용합니다. 헤더에는 별도의 yt010108 글자를 붙이지 않습니다.
- Posts / Notes: 목록, 태그 필터, 상세 화면
- Projects: 프로젝트 목록과 케이스 스터디
- About: 소개, 관심 분야, 활동, 연락처
- 검색: Search 또는 Ctrl+K / Cmd+K
- 테마: 상단 yt010108 옆의 태양·달 버튼으로 라이트·다크 전환. 처음 방문하거나 저장된 선택이 없으면 라이트로 열리며, 직접 선택한 모드는 해당 브라우저에 저장합니다.
- 글 목차: 제목 아래, 본문 위의 펼쳐진 박스에 표시합니다. 제목 단계에 따라 들여쓰며 모바일과 관리자 미리보기에서도 표시합니다.

현재 이름과 GitHub 주소는 `yt010108`로 설정했습니다. `예시` 표시가 붙은 글과 프로젝트는 화면 구성을 보여주는 샘플이며, 실제 게시 이력이나 성과가 아닙니다. 이메일은 비워 두었습니다.

## 콘텐츠 수정

### 관리자와 글쓰기

관리자는 https://yt010108.github.io/admin/#manage, 글쓰기는 https://yt010108.github.io/admin/#write 에서 엽니다. GitHub 연결 후 글과 이미지를 한 커밋으로 발행하고, 기존 GitHub Actions가 블로그를 배포합니다. 처음 연결할 때는 이 저장소 전용 개인 액세스 토큰이 필요합니다. 사용법은 [관리자 가이드](docs/cms.md)를 참고하세요.

- 제목, Posts/Notes, 카테고리, 태그, 글 설명과 작성일
- 기본 편집기와 Markdown 전환, 제목·목록·링크·표·인용·코드 블록
- 기본모드에서 URL만 적은 문단 끝에 Enter를 누르면 원래 링크 아래에 미리보기 카드 생성
- 백틱 3개 뒤에 스페이스로 코드 블록 생성, 백틱 뒤에 python·http 같은 언어 지정 가능
- 이미지 첨부, 붙여넣기, 드래그, 이미지 설명 수정
- 브라우저 IndexedDB에 본문과 이미지를 자동저장, 여러 임시글 이어 쓰기
- 같은 임시글을 여러 탭에서 수정하면 충돌을 알리고 복사본 저장 제공
- 미리보기, Markdown 파일 저장, 이미지가 있으면 Markdown과 이미지를 묶은 ZIP 저장
- 편집용 `.draft.json` 백업 내보내기와 불러오기
- 글 관리: 검색, 상태·종류·카테고리 필터, 페이지 이동, 편집, 복제, 선택한 글의 휴지통 이동·복원
- 관리자 로그인: GitHub 계정·저장소 검증 후 화면 표시, 검증 전 임시글·발행 글 조회 차단
- GitHub 연결 유지: 브라우저에 기억하기 선택 또는 현재 탭 세션만 사용, 로그아웃 시 양쪽 토큰 제거
- 관리자 사이드바: 글쓰기·글 관리·임시저장·휴지통 이동, 데스크톱 고정·모바일 메뉴
- 카테고리·태그: 항목 추가·이름 변경·삭제, 글 수 표시, 글쓰기 선택 목록 연결. 목록은 blog/index.json의 taxonomy에 저장합니다. 이름 변경·삭제는 영향받는 공개 글과 현재 브라우저 저장본을 확인한 뒤 적용하며, 글 본문과 이미지는 유지합니다.
- 발행·수정 발행: 글과 이미지와 목록을 함께 커밋, 다른 변경과 충돌하면 강제 덮어쓰기 없이 중단
- 배포 대기·진행·성공·실패 표시, Actions와 공개 글 링크
- 원격 최신 글 다시 불러오기: 기존 로컬 수정본을 별도 임시글로 보관

임시글은 현재 브라우저에 저장됩니다. 다른 브라우저에서 이어 쓰려면 완료 → 편집용 백업 저장 후, 다른 브라우저의 임시글 → 백업 파일 불러오기를 사용합니다. 브라우저 사이트 데이터를 지우기 전에도 백업 파일을 보관하세요. 이미지는 PNG/JPG/GIF/WebP, 한 장 10MB와 한 글 합계 50MB까지 지원합니다.

본문과 첨부 이미지는 서버로 업로드하지 않습니다. 링크 카드의 제목·설명·이미지는 공개 URL을 Microlink API로 보내 조회합니다. 주소의 해시와 글 본문은 전송하지 않고, localhost·사설 IP나 token·password 등 지정된 민감한 쿼리 매개변수가 있는 주소는 자동 조회하지 않습니다. 외부 이미지 주소는 해당 서버로 요청될 수 있습니다. 편집기 라이브러리는 저장소에 번들로 포함하고 CSP를 적용했습니다.

링크 조회가 실패하거나 API 사용 한도에 도달하면 주소 카드로 남습니다. 카드를 선택하면 정보 다시 불러오기·링크 열기·카드 삭제를 사용할 수 있습니다. 카드 정보는 초안과 백업에 보관하며 Markdown으로 전환하거나 내보낼 때는 HTML 카드로 보존합니다. 코드 블록 끝에서 Enter를 세 번 누르면 일반 문단으로 나옵니다.

개발 시 npm ci --ignore-scripts 후 npm run build, npm test를 실행합니다. GitHub Actions도 같은 빌드와 테스트를 실행합니다. 관리자 원본은 admin/src/, 배포 번들은 admin/assets/이며 라이선스 고지를 함께 배포합니다. _site/가 최종 배포 폴더입니다.

admin/assets/ 전체, assets/posts.js, published.js, _site/는 빌드 산출물이므로 Git으로 추적하지 않습니다. 새로 저장소를 받으면 먼저 빌드해 생성합니다. 관리자 라이선스 고지도 빌드 중 생성하고 배포 파일에 포함합니다.

발행한 글은 blog/entries/에 문서 JSON으로 저장하고 blog/index.json이 목록과 파일 버전을 관리합니다. 이미지는 assets/uploads/에 저장합니다. 공개 빌드는 발행 상태의 글만 published.js에 포함하며, 브라우저에서 임시저장한 글과 휴지통 글은 포함하지 않습니다. 공개 저장소에 발행한 글은 휴지통으로 옮겨도 Git 이력에 남습니다.

### 공개 블로그 콘텐츠

content.js에서 이름, 소개, 연락처, 프로젝트와 초기 구성 예시를 수정합니다. 실제 Posts·Notes는 관리자에서 발행합니다. 해당 종류의 첫 실제 글을 발행하면 구성 예시 대신 실제 글을 보여주며, 마지막 실제 글을 휴지통으로 옮겨도 구성 예시를 다시 표시하지 않습니다.

열어 둔 블로그도 메뉴 이동, 검색, 다른 탭에서 돌아올 때 최신 배포를 확인합니다. 화면이 열린 동안에는 30초마다 확인하며, 배포가 바뀐 경우에만 글 데이터를 다시 불러옵니다. 새 글 주소는 최신 목록을 확인한 뒤 표시하고, 연결 실패나 아직 없는 글에는 다시 확인 버튼을 제공합니다.

| 파일 | 역할 |
| --- | --- |
| `index.html` | 공통 화면과 메뉴 |
| `styles.css` | 색상, 글꼴, 간격, 반응형 스타일 |
| `app.js` | 화면 이동, 필터, 검색, 코드 복사 |
| `theme.js` | 첫 화면 테마 적용, 모드 전환, 선택 저장 |
| `content.js` | 프로필과 콘텐츠 |
| `assets/favicon.svg` | 기본 아이콘 |
| `404.html` | 없는 주소 안내 |
| blog/index.json, blog/entries/ | 관리자가 발행한 글과 파일 버전 |
| shared/posts.js | 관리자 미리보기와 공개 글의 공통 렌더러 |
| published.js | 빌드가 생성하는 공개 글 데이터 |
| assets/post.css, assets/posts.js | 공개 글의 서식과 렌더러 번들 |
| `.nojekyll` | 정적 파일을 그대로 배포하도록 지정 |

`profile.github`, `profile.email`, 프로젝트별 `github`에 실제 링크를 지정할 수 있습니다. 예시를 실제 내용으로 바꾼 뒤 해당 항목의 `sample`을 `false`로 바꾸면 예시 표시가 사라집니다.

글의 `body`는 `lead`, `heading`, `paragraph`, `code`, `list`, `callout` 블록으로 구성됩니다. `heading.id`는 목차 이동에 사용하므로 글 안에서 중복되지 않게 지정합니다.

## 로컬에서 확인

저장소 폴더에서 의존성을 설치하고 빌드한 뒤, 생성된 _site/를 실행합니다.

```powershell
npm ci --ignore-scripts
npm run build
npm test
python -m http.server 8781 --bind 127.0.0.1 --directory _site
```

브라우저에서 `http://127.0.0.1:8781/`을 엽니다.

## 배포

main에 변경 사항을 반영하면 .github/workflows/deploy.yml이 편집기·공개 글을 빌드하고 테스트한 뒤 _site/를 GitHub Pages에 배포합니다. 글 목록과 JSON·이미지 버전이 일치하지 않으면 배포 빌드가 실패해 이전 사이트를 유지합니다. 별도의 정적 사이트 생성기나 Ruby 설치는 필요하지 않습니다.

현재는 #/posts, #/post/글-ID 같은 해시 주소로 화면을 전환합니다. 공개 글은 제목·설명·태그·카테고리·본문으로 검색할 수 있고, 표·첨부 이미지·링크 카드·코드·목차를 지원합니다. 검색 노출용 개별 경로와 RSS 등은 이후 작업입니다.

## 기존 콘텐츠 보존

기존 _posts/의 학습 글과 첨부 이미지는 원본 콘텐츠로 보관합니다. 새 화면의 목록에는 아직 자동으로 연결되지 않습니다. 사용하지 않는 Jekyll 설정·Ruby 의존성·기본 예제와 Obsidian 설정·플러그인은 정리했습니다. Obsidian 설정과 빌드 산출물은 .gitignore로 제외합니다.

교체 직전 버전은 `backup/pre-security-blog-2026-10-22` 브랜치와 Git 이력에서 확인할 수 있습니다.
