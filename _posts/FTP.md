FTP(File Transfer Protocol, 파일 전송 프로토콜)는 네트워크를 통해 컴퓨터 파일을 전송하기 위한 표준 통신 규약입니다. 1970년대에 개발되어 인터넷 초기부터 현재까지 파일 업로드 및 다운로드에 널리 사용되어 왔습니다.

다음은 FTP의 개념, 작동 방식, 특징 및 현대적 사용에 대한 상세한 설명입니다.

---

## 1.  FTP의 정의 및 목적

FTP는 클라이언트(사용자 컴퓨터)와 서버 간에 파일을 전송하는 데 사용됩니다. 주요 목적은 다음과 같습니다:

- **파일 공유:** 원격 서버에 저장된 파일을 다른 사용자와 공유할 수 있게 합니다.
    
- **웹사이트 관리:** 웹 개발자가 로컬 컴퓨터에서 웹 서버로 웹 페이지, 이미지, 스크립트 등의 파일을 업로드하거나 업데이트하는 데 사용합니다.
    
- **데이터 백업 및 복구:** 서버 간에 대량의 데이터를 이동하거나 백업하는 용도로 활용됩니다.
    

---

## 2. FTP 작동 방식

FTP는 **클라이언트-서버 모델**을 기반으로 작동하며, 데이터를 전송하기 위해 두 개의 별도 연결을 사용한다는 특징이 있습니다.

### 2.1. 두 개의 연결

FTP는 효율적인 파일 전송을 위해 **제어 연결**과 **데이터 연결**을 분리합니다.

- **제어 연결 (Control Connection):**
    
    - **포트 21 (기본):** 클라이언트와 서버 간의 인증(사용자 이름, 비밀번호) 및 명령(파일 목록 보기, 디렉토리 변경, 파일 전송 시작/중지 등)을 주고받는 데 사용됩니다. 이 연결은 FTP 세션이 유지되는 동안 계속 활성화되어 있습니다.
        
- **데이터 연결 (Data Connection):**
    
    - **포트 20 (기본) 또는 동적 포트:** 실제 파일 데이터가 전송되는 경로입니다. 파일 업로드 또는 다운로드가 발생할 때마다 이 연결이 설정되고 데이터 전송이 완료되면 닫힙니다.
        

### 2.2. 연결 모드: 액티브 모드(Active Mode)와 패시브 모드(Passive Mode)

FTP는 데이터를 전송하는 방식에 따라 두 가지 모드로 작동합니다.

- **액티브 모드 (Active Mode):**
    
    - 클라이언트가 서버의 포트 21로 접속하여 데이터 전송 요청을 보냅니다.
        
    - 이후 서버가 클라이언트의 임의의 포트로 데이터 연결을 시도합니다.
        
    - **단점:** 클라이언트 측에 방화벽이 있을 경우, 서버의 연결 시도를 차단하여 데이터 전송이 실패할 수 있습니다.
        
- **패시브 모드 (Passive Mode):**
    
    - 클라이언트가 서버의 포트 21로 접속하여 패시브 모드를 요청합니다.
        
    - 서버는 데이터 전송을 위해 사용할 동적 포트 번호를 클라이언트에게 알려줍니다.
        
    - 클라이언트가 서버가 알려준 동적 포트로 데이터 연결을 시작합니다.
        
    - **장점:** 대부분의 방화벽 환경에서 작동하므로 현재 가장 일반적으로 사용되는 방식입니다.

## 3. FTP의 특징 및 단점

### 장점

- **널리 사용됨:** 대부분의 운영 체제와 웹 브라우저가 FTP를 지원합니다.
    
- **간편한 설정 및 사용:** 설정이 비교적 간단하며, 전용 FTP 클라이언트 소프트웨어(예: FileZilla)를 사용하면 편리하게 파일을 관리할 수 있습니다.
    
- **대량 파일 전송에 유리:** 웹 브라우저 기반의 HTTP 전송보다 대량의 파일을 일괄적으로 빠르게 전송하는 데 유리합니다.
    

### 단점 (주요 보안 문제)

- **암호화 부재:** 표준 FTP는 데이터와 사용자 인증 정보(ID, 비밀번호)를 **평문(암호화되지 않은 텍스트)**으로 전송합니다.
    
- **보안 취약성:** 이로 인해 네트워크를 도청(Sniffing)하는 해커에게 데이터가 노출될 위험이 매우 큽니다. 특히 중요한 데이터나 로그인 정보가 쉽게 가로채일 수 있습니다.
    

---

## 4. FTP의 발전: 보안 프로토콜

표준 FTP의 보안 취약점 때문에 현대에는 보안 기능이 강화된 프로토콜들이 주로 사용됩니다.

### FTPS (FTP Secure)

FTP에 SSL/TLS(Secure Sockets Layer/Transport Layer Security) 암호화를 추가한 것입니다. FTP의 기능은 유지하면서 전송되는 데이터와 로그인 정보를 암호화합니다.

### SFTP (SSH File Transfer Protocol)

FTP와는 다른 프로토콜로, SSH(Secure Shell)를 기반으로 합니다. FTP와 달리 **하나의 채널**만 사용하며, SSH의 강력한 암호화 기능을 활용하여 데이터 전송의 보안성을 극대화합니다. SFTP는 FTP보다 훨씬 안전하며, 대부분의 기업 환경에서 파일을 전송하는 표준으로 자리 잡았습니다.
